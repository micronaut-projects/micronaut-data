Micronaut Data Azure Cosmos supports building queries programmatically at runtime using the Jakarta Persistence Criteria API. The repository interfaces, the specification types and how to use them for querying, updating and deleting are the same for all Micronaut Data modules and are described in the <<criteriaSpecifications, Repositories with Jakarta Criteria API>> section, including the async, reactive and coroutine <<otherRepositoryVariations, repository variations>>.

Micronaut Data implements a subset of Jakarta Persistence Criteria API 3.0, which can be used for Micronaut Data Azure Cosmos features. To utilize this feature add the following dependency:

dependency:jakarta.persistence:jakarta.persistence-api[]

Then extend api:data.repository.jpa.JpaSpecificationExecutor[] (or one of its variations) in a ann:data.cosmos.annotation.CosmosRepository[] repository:

snippet::example.PersonRepository[project-base="doc-examples/azure-cosmos-example",source="main" tags="repository",indent="0"]

Micronaut Criteria API currently implements only a subset of the API. Most of it is internally used to create queries with predicates and projections.

Currently, not supported JPA Criteria API features:

- Joins with custom `ON` expressions and typed join methods like `joinSet` etc
- Sub-queries
- Collection operations: `isMember` etc
- Custom or tuple result type
- Transformation expressions like concat, substring etc.
- Cases and functions
