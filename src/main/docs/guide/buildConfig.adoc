Micronaut Data generates repository implementations at compilation time, so every application needs two things:

1. The Micronaut Data *annotation processor*, which computes the queries while your code compiles.
2. A *runtime module* for your database, together with the database driver and, for JDBC, a connection pool.

If only the annotation processor is present, annotations such as `@Repository` do not resolve. If the runtime module, driver or connection pool is missing, the application compiles but fails at startup, typically with `No bean of type [io.micronaut.data.operations.PrimaryRepositoryOperations] exists`.

The quickest way to get a working build is to generate a project with https://micronaut.io/launch[Micronaut Launch] and select the `data-jdbc`, `data-r2dbc`, `data-jpa`, `data-mongodb` or `data-azure-cosmos` feature together with a database driver feature. To add Micronaut Data to an existing project, follow the steps below.

=== Step 1: Choose a Module

[cols="1,2,2"]
|===
|Module |Runtime dependency |Also required at runtime

|<<jdbc, JDBC>>
|`io.micronaut.data:micronaut-data-jdbc`
|A JDBC driver and a connection pool, for example `io.micronaut.sql:micronaut-jdbc-hikari`

|<<r2dbc, R2DBC>>
|`io.micronaut.data:micronaut-data-r2dbc`
|An R2DBC driver, for example `org.postgresql:r2dbc-postgresql`

|<<hibernate, JPA (Hibernate)>>
|`io.micronaut.data:micronaut-data-hibernate-jpa`
|A JDBC driver and a connection pool, for example `io.micronaut.sql:micronaut-jdbc-hikari`

|<<hibernateReactive, Hibernate Reactive>>
|`io.micronaut.data:micronaut-data-hibernate-reactive`
|A Vert.x SQL client, for example `io.vertx:vertx-pg-client`

|<<mongo, MongoDB>>
|`io.micronaut.data:micronaut-data-mongodb`
|`org.mongodb:mongodb-driver-sync` or `org.mongodb:mongodb-driver-reactivestreams`

|<<azureCosmos, Azure Cosmos>>
|`io.micronaut.data:micronaut-data-azure-cosmos`
|-
|===

Versions are managed by the Micronaut platform BOM, which is applied automatically by the Micronaut Gradle and Maven plugins, so no version numbers are needed.

=== Step 2: Add the Annotation Processor

For SQL databases (JDBC, R2DBC, JPA and Hibernate Reactive) add `micronaut-data-processor`:

dependency:io.micronaut.data:micronaut-data-processor[scope="annotationProcessor"]

For document databases (<<mongo, MongoDB>> and <<azureCosmos, Azure Cosmos>>) add `micronaut-data-document-processor` instead:

dependency:io.micronaut.data:micronaut-data-document-processor[scope="annotationProcessor"]

NOTE: For Kotlin, add the processor in https://docs.micronaut.io/latest/guide/#kaptOrKsp[kapt or ksp scope]. For Groovy, add it in `compileOnly` scope.

=== Step 3: Add the Runtime Dependencies

For example, a JDBC application using PostgreSQL needs:

dependency:io.micronaut.data:micronaut-data-jdbc[]

dependency:io.micronaut.sql:micronaut-jdbc-hikari[scope="runtimeOnly"]

dependency:org.postgresql:postgresql[scope="runtimeOnly"]

And a JPA application using PostgreSQL needs:

dependency:io.micronaut.data:micronaut-data-hibernate-jpa[]

dependency:io.micronaut.sql:micronaut-jdbc-hikari[scope="runtimeOnly"]

dependency:org.postgresql:postgresql[scope="runtimeOnly"]

==== Why a connection pool is required

Micronaut Data JDBC and Micronaut Data JPA do not open database connections themselves. They obtain connections from a `javax.sql.DataSource` bean, and that bean is created, from the `datasources.*` configuration, by one of the connection pool modules of https://micronaut-projects.github.io/micronaut-sql/latest/guide/#jdbc[Micronaut SQL]:

* `io.micronaut.sql:micronaut-jdbc-hikari` (recommended)
* `io.micronaut.sql:micronaut-jdbc-tomcat`
* `io.micronaut.sql:micronaut-jdbc-dbcp`
* `io.micronaut.sql:micronaut-jdbc-ucp` (Oracle Universal Connection Pool)

Without one of these modules no `DataSource` is created, no repository operations bean can be created for the data source, and repository injection fails with `No bean of type [io.micronaut.data.operations.PrimaryRepositoryOperations] exists`.

The R2DBC, Hibernate Reactive, MongoDB and Azure Cosmos modules connect through their own clients and do not need a JDBC pool. An R2DBC application that runs migrations with Flyway or Liquibase still needs a JDBC driver and pool for the migration tool.

=== Step 4: Configure the Data Source

Each module is configured in the application configuration file. See the quick start of your module: <<jdbcQuickStart, JDBC>>, <<r2dbcQuickStart, R2DBC>>, <<hibernateQuickStart, JPA>>, <<hibernateReactive, Hibernate Reactive>>, <<mongoQuickStart, MongoDB>> or <<azureCosmosQuickStart, Azure Cosmos>>.

=== Micronaut Data and Lombok

If you intend to use Lombok with Micronaut Data then you must place the Lombok annotation processor *before* the Micronaut processors in your build configuration since Micronaut needs to see the mutations to the AST that Lombok applies.

WARNING: Lombok plugins like the Gradle plugin `io.franzbecker.gradle-lombok` are not supported as they place the annotation processors in an incorrect order.
