Unlike JPA/Hibernate, Micronaut Data JDBC / R2DBC is stateless and has no notion of a persistence session that requires state management.

Since there is no session, features like dirty checking are not supported. This has implications when defining repository methods for inserts and updates.

When saving an entity with a method like `save(MyEntity)`, Micronaut Data JDBC / R2DBC decides between a SQL `INSERT` and `UPDATE` from the entity identity value.
An entity without an assigned identity value is inserted.
An entity with an assigned identity value is updated.

If you need to require an insert, use `insert(MyEntity)`, `insertAll(Iterable<MyEntity>)`, or define an insert method.
