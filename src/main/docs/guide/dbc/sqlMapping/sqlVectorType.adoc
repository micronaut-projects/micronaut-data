Micronaut Data provides first-class support for storing and retrieving numeric embeddings as SQL vector columns.

Supported platforms (since 5.0.0):
- Oracle Database 23ai VECTOR columns (JDBC and R2DBC)
- PostgreSQL pgvector (JDBC and R2DBC)

Micronaut Data includes a lightweight, immutable vector abstraction in the `io.micronaut.data.model.vector` package:

- `Vector` (sealed interface)
- `DoubleVector` (backed by `double[]`)
- `FloatVector` (backed by `float[]`)
- `IntVector` (backed by `int[]`)
- `ByteVector` (backed by `byte[]`)

Factory methods are available via `Vector.of(...)` for convenience:

[source,java]
----
import io.micronaut.data.model.vector.Vector;

Vector v1 = Vector.of(1d, 2.5d, -3.75d); // returns a DoubleVector
Vector v2 = Vector.of(1f, 2f, 3f);       // returns a FloatVector
Vector v3 = Vector.of(1,2,3);            // returns an IntVector
Vector v4 = Vector.of((byte)1,(byte)2);  // returns a ByteVector
----

Vector values are converted to/from datastore-specific SQL types via Micronaut converters with full support in JDBC and R2DBC.

== Oracle Database (VECTOR)

Oracle VECTOR columns are supported when the repository uses the Oracle dialect.

Key points:
- Entities with VECTOR fields are supported on Oracle; schema generation emits `VECTOR` column types.
- Oracle’s JDBC and R2DBC drivers surface VECTOR values as primitive arrays depending on element type; Micronaut maps those to the corresponding `Vector` implementations.

Oracle driver mapping (read path):
- `VECTOR(*, *)` and `VECTOR(..., FLOAT64)` → `double[]` → `DoubleVector`
- `VECTOR(..., FLOAT32)` → `float[]` → `FloatVector`
- `VECTOR(..., INT8)` → `int[]` → `IntVector`
- `VECTOR(..., BINARY)` → `byte[]` → `ByteVector`

=== DDL and schema generation (Oracle)

For Oracle, VECTOR properties map to `VECTOR`. You can (and should) specify dimensions and element type explicitly in the DDL or via `@MappedProperty(definition = "...")`.

Examples:
[source,sql]
----
CREATE TABLE vector_doc (id NUMBER PRIMARY KEY, embedding VECTOR(3, FLOAT64));
CREATE TABLE vector_float_doc (id NUMBER PRIMARY KEY, embedding VECTOR(3, FLOAT32));
CREATE TABLE vector_int_doc (id NUMBER PRIMARY KEY, embedding VECTOR(3, INT8));
CREATE TABLE vector_byte_doc (id NUMBER PRIMARY KEY, embedding VECTOR(3, BINARY));
----

Using `@MappedProperty` to set the column definition:
[source,java]
----
import io.micronaut.data.annotation.*;
import io.micronaut.data.model.vector.DoubleVector;

@MappedEntity("vector_doc")
class VectorDoc {
  @Id
  @GeneratedValue(value = GeneratedValue.Type.SEQUENCE, ref = "VECTOR_DOC_SEQ")
  Long id;

  // Explicit DDL (dimension + element type)
  @MappedProperty(definition = "VECTOR(3, FLOAT64)")
  DoubleVector embedding;
}
----

If no definition is provided, schema generation can use a generic `VECTOR` type. For production systems, prefer supplying the exact VECTOR definition (dimensions and element type).

=== JDBC binding/reading (Oracle)

- Write path: `Vector` values are unwrapped to primitive arrays (`double[]`, `float[]`, `int[]`, `byte[]`) before binding; the Oracle driver writes them to VECTOR columns.
- Read path: Result values are read as primitive arrays and adapted back into the appropriate `Vector` implementation.
- Dedicated converters handle cases where `oracle.sql.VECTOR` is returned directly.

=== Example: JDBC repository (Oracle)

[source,java]
----
import io.micronaut.data.annotation.*;
import io.micronaut.data.jdbc.annotation.JdbcRepository;
import io.micronaut.data.model.query.builder.sql.Dialect;
import io.micronaut.data.repository.CrudRepository;
import io.micronaut.data.model.vector.DoubleVector;

@MappedEntity("vector_double_doc")
public class VectorDoubleDoc {
  @Id
  @GeneratedValue(value = GeneratedValue.Type.SEQUENCE, ref = "VECTOR_DOC_SEQ")
  Long id;

  // Defaults to FLOAT64 semantics
  DoubleVector embedding;

  // getters/setters omitted
}

@JdbcRepository(dialect = Dialect.ORACLE)
interface VectorDoubleDocRepository extends CrudRepository<VectorDoubleDoc, Long> {
}
----

== PostgreSQL (pgvector)

PostgreSQL vector support targets the https://github.com/pgvector/pgvector[pgvector] extension.

Requirements:
- PostgreSQL with pgvector installed (e.g., `CREATE EXTENSION IF NOT EXISTS vector;`)
- Dialect set to POSTGRES
- JDBC: Driver exposes `org.postgresql.util.PGobject` with type `vector`
- R2DBC: Driver exposes `io.r2dbc.postgresql.codec.Vector`

=== DDL (PostgreSQL)

[source,sql]
----
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE vector_doc (
  id BIGINT PRIMARY KEY,
  embedding vector(3)
);
----

Micronaut’s converters will map:
- JDBC: `DoubleVector`/`FloatVector`/`IntVector`/`ByteVector` → `PGobject(type="vector")` with vector text
- R2DBC: vector values ↔︎ `io.r2dbc.postgresql.codec.Vector`

=== Example: JDBC repository (PostgreSQL)

[source,java]
----
import io.micronaut.data.annotation.*;
import io.micronaut.data.jdbc.annotation.JdbcRepository;
import io.micronaut.data.model.query.builder.sql.Dialect;
import io.micronaut.data.repository.CrudRepository;
import io.micronaut.data.model.vector.DoubleVector;

@MappedEntity("vector_doc")
class PgVectorDoc {
  @Id
  @GeneratedValue
  Long id;

  DoubleVector embedding;
}

@JdbcRepository(dialect = Dialect.POSTGRES)
interface PgVectorDocRepository extends CrudRepository<PgVectorDoc, Long> {
}
----

=== Example: R2DBC repository (PostgreSQL)

[source,java]
----
import io.micronaut.data.annotation.*;
import io.micronaut.data.r2dbc.annotation.R2dbcRepository;
import io.micronaut.data.model.query.builder.sql.Dialect;
import io.micronaut.data.repository.reactive.ReactorCrudRepository;
import io.micronaut.data.model.vector.FloatVector;

@MappedEntity("vector_doc")
class PgVectorR2dbcDoc {
  @Id
  @GeneratedValue
  Long id;

  FloatVector embedding;
}

@R2dbcRepository(dialect = Dialect.POSTGRES)
interface PgVectorR2dbcDocRepository extends ReactorCrudRepository<PgVectorR2dbcDoc, Long> {
}
----

== Custom queries

For custom SQL via `@Query`, pass `Vector` or a specific implementation:

[source,java]
----
import io.micronaut.data.annotation.Query;
import io.micronaut.data.annotation.Parameter;
import java.util.Optional;
import io.micronaut.data.model.vector.Vector;

@JdbcRepository(dialect = Dialect.ORACLE) // or POSTGRES
interface VectorDocCustom {
  @Query("INSERT INTO vector_double_doc(id, embedding) VALUES (VECTOR_DOC_SEQ.nextval, :vec)")
  void saveCustom(@Parameter("vec") Vector vec);

  @Query("UPDATE vector_double_doc SET embedding = :vec WHERE id = :id")
  void updateCustom(Long id, @Parameter("vec") Vector vec);

  @Query("SELECT * FROM vector_double_doc WHERE id = :id")
  Optional<VectorDoubleDoc> findById(Long id);
}
----

== Notes and best practices

- Prefer explicit VECTOR column definitions (dimensions + element type) in Oracle.
- Ensure pgvector is installed and configured on PostgreSQL before using vector columns.
- Choose the most appropriate `Vector` class to match your column type (e.g. `DoubleVector` for `VECTOR(..., FLOAT64)` or `vector(...)` in PostgreSQL).
- Converters and column definition helpers are dialect-aware; repositories must declare the correct dialect.
