This section explains how to map and use vector embeddings with Micronaut Data.

Micronaut Data ships lightweight value types under `io.micronaut.data.model.vector`:

- `FloatVector` — float[]-backed (good size/speed balance; recommended default)
- `DoubleVector` — double[]-backed (best precision; bigger payloads)
- `ByteVector` — byte[]-backed (smallest size; lossy/narrowed)

You can also use the sealed interface `Vector` if you need a type-agnostic parameter which is preferred way of using it. When you use `Vector`, Micronaut Data will by default choose the optimal database-specific representation for the configured dialect/driver.

To create a vector index, annotate the vector property with @VectorIndex (params: name optional, vectorIndexType IVF|HNSW, distanceType, accuracy).
Dialect notes:
- PostgreSQL (pgvector): Creates ivfflat/hnsw; operator class is derived from distance (e.g. COSINE -> vector_cosine_ops, DOT -> vector_ip_ops, L1/L2 -> vector_l1_ops/vector_l2_ops, HAMMING/JACCARD on bit vectors).
- Oracle: Creates CREATE VECTOR INDEX with ORGANIZATION NEIGHBOR PARTITIONS (IVF) or GRAPH (HNSW), uses DISTANCE and target ACCURACY.

=== DDL generation and dimensions

Micronaut Data honors `@jakarta.persistence.Column(length = N)` to set vector dimensions (when the vendor supports it):

- PostgreSQL (pgvector): `vector(N)` when length is present, otherwise `vector`
- Oracle: `VECTOR(N, <TYPE>)` or `VECTOR(*, <TYPE>)` when no length is present
- MySQL HeatWave: `VECTOR(N)` or `VECTOR`

The Oracle `<TYPE>` is inferred from the vector subtype:
- `DoubleVector` -> `FLOAT64`
- `FloatVector`  -> `FLOAT32`
- `ByteVector`   -> `INT8`

If the dialect does not support vectors, Micronaut falls back to `VARCHAR(255)` to avoid schema generation failure.


=== PostgreSQL (pgvector)

- Column type: `vector` or `vector(N)`
- Only `FloatVector` is supported.
- Use `@Column(length = N)` to define the dimension in schema generation

DDL example:
[source,sql]
----
CREATE TABLE document_embedding (
  id BIGINT PRIMARY KEY,
  embedding vector(384)
);
----

=== Oracle (VECTOR)

- Column type: `VECTOR(N, <TYPE>)` or `VECTOR(*, <TYPE>)`
- `<TYPE>` derives from the Java vector subtype:
  - `DoubleVector` -> `FLOAT64`
  - `FloatVector`  -> `FLOAT32`
  - `ByteVector`   -> `INT8`
- Use `@Column(length = N)` to set the dimension; when omitted, `*` is used.

DDL example:
[source,sql]
----
CREATE TABLE document_embedding (
  id NUMBER(19) PRIMARY KEY,
  embedding VECTOR(384, FLOAT64)
);
----

=== MySQL HeatWave (VECTOR)

- Column type: `VECTOR(N)` or `VECTOR`
- Only `FloatVector` is supported.
- Works with JDBC only; R2DBC is currently not supported.
- Use `@Column(length = N)` to define the dimension

DDL example:
[source,sql]
----
CREATE TABLE document_embedding (
  id BIGINT PRIMARY KEY,
  embedding VECTOR(1536)
);
----
