The `micronaut-data-postgres-age` module stores graphs in PostgreSQL with the https://age.apache.org[Apache AGE] extension. It runs Cypher through the `cypher()` function on the JDBC data source, so it shares connections and transactions with Micronaut Data JDBC.

dependency:io.micronaut.data:micronaut-data-postgres-age[]

Repositories are annotated with ann:data.age.annotation.AgeRepository[], whose value names the data source.

[configuration]
----
datasources:
  default:
    url: jdbc:postgresql://localhost:5432/graphs
micronaut:
  data:
    age:
      graph: movies
      create-graph: true
      create-extension: false
----

The graph named by `micronaut.data.age.graph` is created on first use unless `create-graph` is `false`. Set `create-extension` to `true` to run `CREATE EXTENSION age`, which needs a privileged user. An application with several data sources names the graph of each under `micronaut.data.age.graphs`, keyed by the data source name; a data source without an entry uses `micronaut.data.age.graph`:

[configuration]
----
micronaut:
  data:
    age:
      graph: movies
      graphs:
        reporting: analytics
----

Apache AGE implements a subset of Cypher, which the module accounts for at build time:

* Nodes have a single label.
* There is no `shortestPath()`: shortest paths are the shortest of all paths up to the maximum depth, so path finders need ann:data.graph.annotation.PathLimit[].
* Identifiers generated by the database are graph ids, mapped to `Long`.
* Temporal values are stored as ISO 8601 strings.

== Graphs per tenant

An Apache AGE graph is a schema of the database, so with the <<multitenancy, multi-tenancy>> mode `SCHEMA` the tenant names the graph: each operation runs on the graph of the tenant resolved for the current request, and on the configured graph when there is no tenant. The graph is named after the tenant id, after the optional `tenant-graph-prefix`, unless `tenant-graphs` maps the tenant to another name:

[configuration]
----
micronaut:
  multitenancy:
    tenantresolver:
      httpheader:
        enabled: true
  data:
    multi-tenancy:
      mode: SCHEMA
    age:
      graph: movies
      tenant-graph-prefix: tenant_
      tenant-graphs:
        acme: acme_movies
----

With this configuration a request of the tenant `acme` runs on the graph `acme_movies`, and one of the tenant `globex` on `tenant_globex`. A tenant graph that does not exist is created on first use under the same `create-graph` setting as the configured graph, with the indexes of the entities when `create-indexes` is enabled. A graph name must be a plain identifier, as it is written into the `cypher()` call: a tenant id that is not one is rejected before any statement runs, so a tenant resolver may pass the id through, but applications must still ensure it names only graphs the caller may access.

The tenant comes from the api:data.runtime.multitenancy.TenantResolver[] of Micronaut Data, which reads the `TenantResolver` of https://micronaut-projects.github.io/micronaut-multitenancy/latest/guide/[Micronaut Multitenancy] when it is on the classpath. To name the graph another way, for example from a lookup of the tenant, declare a bean of api:data.graph.runtime.age.AgeGraphTenantResolver[], whose `resolveTenantGraph()` returns the graph name or `null` for the configured graph.

With the mode `DATASOURCE`, the tenant names the data source instead, and the graph of each data source is configured under `micronaut.data.age.graphs`.

== Reactive repositories with R2DBC

To run graph repositories on the non-blocking https://github.com/pgjdbc/r2dbc-postgresql[PostgreSQL R2DBC driver], use the `micronaut-data-postgres-age-r2dbc` module in place of `micronaut-data-postgres-age`, with the driver:

dependency:io.micronaut.data:micronaut-data-postgres-age-r2dbc[]

dependency:org.postgresql:r2dbc-postgresql[scope="runtimeOnly"]

The repositories run on an R2DBC connection factory of https://micronaut-projects.github.io/micronaut-r2dbc/latest/guide/[Micronaut R2DBC], with the same `micronaut.data.age` settings:

<1> The repository runs Cypher on Apache AGE over R2DBC. Queries are compiled to the same `cypher()` statements as on JDBC.
<2> `ReactorCrudRepository` provides reactive create, read, update and delete operations.

snippet::example.MovieRepositorySpec[project-base="doc-examples/age-r2dbc-example", tags="reactive", indent="0", languages="java,kotlin,groovy,python"]

<1> Saving movies writes their nodes and relationships with Cypher.
<2> Then stream the movies directed by Lana Wachowski.
<3> Block only to read the result in the test.

Queries and writes run in the same reactive connection, and join the transaction of a reactive `@Transactional` method. AGE is loaded, and its catalog put on the search path, on the connection before each operation, since pooled connections may not have been prepared. Blocking methods are not supported, and indexes declared on entities are created by the JDBC module only.

Graphs per tenant work as on JDBC. The tenant is resolved when an operation is subscribed to, on the subscribing thread, through the same blocking `TenantResolver`: a resolver that reads the HTTP request finds it in the propagated context of the request, as the resolvers of Micronaut Multitenancy do.
