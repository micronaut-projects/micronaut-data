Repositories are annotated with ann:data.oracle.graph.annotation.OracleGraphRepository[], which names the graph, as shown in the <<graphOracleQuickStart, quick start>>. Queries are compiled to SQL/PGQ `GRAPH_TABLE` queries, the property graph queries of the SQL standard, which run on any Oracle Database 23ai data source. Path finders check for paths and count them, with `existsPath` and `countPaths`, and `findAllPaths` returns every path up to the maximum depth, shortest first, on a release whose `GRAPH_TABLE` supports `ONE ROW PER STEP`, such as Oracle AI Database 26ai. Shortest path finders fail at build time, as `GRAPH_TABLE` has no shortest path search. A path takes each relationship once, as in Cypher, and a path over several relationship types names them after `By`, as SQL/PGQ cannot read the label of an edge. `StartsWith`, `EndsWith` and `Contains` are supported through `LIKE`.

Property graphs over tables are read only views: write the tables with a JDBC repository, for example a ann:data.jdbc.annotation.JdbcRepository[] over the same entities. Path finders need a maximum depth set with ann:data.graph.annotation.PathLimit[], either on the method or on an `int` parameter, whose argument is capped by `micronaut.data.graph.max-path-depth` as described in <<graphPaths, Paths and Shortest Paths>>. Relationship finders need a single relationship type. An undirected relationship finder returns each relationship with the nodes it starts and ends at as stored in its edge table, whichever argument matched which end, as Neo4j does.
