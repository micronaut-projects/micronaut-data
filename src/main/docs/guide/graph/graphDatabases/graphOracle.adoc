The `micronaut-data-oracle-graph` module queries property graphs that Oracle Database defines over tables with `CREATE PROPERTY GRAPH`, such as the bank transfers graph of the https://github.com/oracle-samples/oracle-graph[Oracle graph samples]:

[source,sql]
----
CREATE PROPERTY GRAPH bank_graph
  VERTEX TABLES (accounts KEY (id) LABEL Account PROPERTIES (id, name))
  EDGE TABLES (transfers KEY (id)
    SOURCE KEY (src) REFERENCES accounts (id)
    DESTINATION KEY (dst) REFERENCES accounts (id)
    LABEL TRANSFERS PROPERTIES (id, amount))
----

dependency:io.micronaut.data:micronaut-data-oracle-graph[]

Repositories are annotated with ann:data.oracle.graph.annotation.OracleGraphRepository[], which names the graph and the query language:

[source,java]
----
@OracleGraphRepository(graph = "bank_graph", language = PropertyGraph.QueryLanguage.SQL_PGQ)
public interface BankGraph extends GenericRepository<Account, Long> {

    List<Account> findByTransfersAmountGreaterThan(BigDecimal amount);

    @PathLimit(3)
    boolean existsPathByTransfers(Long from, Long to);

    @Query("SELECT * FROM GRAPH_TABLE (bank_graph MATCH (a IS Account) -[t IS TRANSFERS]-> (b IS Account) WHERE t.amount > $amount COLUMNS (a.name AS \"source\", b.name AS \"target\", t.amount AS \"amount\"))")
    List<TransferView> largeTransfers(BigDecimal amount);
}
----

The query language is one of:

`PGQL`:: The default. Queries are compiled to https://pgql-lang.org[PGQL] and need a data source that uses the PGQL JDBC driver from `com.oracle.database.graph:opg-pgql-jdbc`. Path finders return paths with `ANY SHORTEST`, `ALL SHORTEST` and `ALL` searches.
`SQL_PGQ`:: Queries are compiled to SQL/PGQ `GRAPH_TABLE` queries, which run on any Oracle Database 23ai data source. Path finders check for paths and count them, and `StartsWith`, `EndsWith` and `Contains` are supported through `LIKE`.

Path finders need a fixed maximum depth set with ann:data.graph.annotation.PathLimit[] on the method, and relationship finders a single relationship type.

== Writing nodes

A property graph over tables is a view, so its repositories write nodes to their vertex tables with SQL, as Micronaut Data JDBC does. The value of ann:data.graph.annotation.Node[] names the vertex table, and `labels` the label the graph gives it:

[source,java]
----
@Node(value = "accounts", labels = "Account")
public record Account(@Id Long id, String name, @Relationship("TRANSFERS") List<Transfer> transfers) {
}
----

Save, update and delete methods, including those of api:data.repository.CrudRepository[], are compiled to SQL for Oracle at build time and run by the JDBC repository operations of the same data source:

[source,java]
----
@OracleGraphRepository(graph = "bank_graph", language = PropertyGraph.QueryLanguage.SQL_PGQ)
public interface BankGraph extends CrudRepository<Account, Long> {
}
----

[source,java]
----
bankGraph.save(new Account(5L, "Erin", List.of()));                  // INSERT INTO "ACCOUNTS" ("NAME","ID") VALUES (?,?)
List<Account> erin = bankGraph.findByNameStartsWithOrderByName("Er"); // SELECT * FROM GRAPH_TABLE (bank_graph MATCH (n IS Account) ...)
----

Writes join the current connection and transaction of the data source, as graph queries do. Writes need the `micronaut-data-jdbc` module, which `micronaut-data-oracle-graph` depends on. Saving a node writes only its row: relationships are rows of their edge tables, which a ann:data.jdbc.annotation.JdbcRepository[] over an entity of the edge table writes.
