Graph entities are mapped with the annotations of the `io.micronaut.data.graph.annotation` package, which build on the Micronaut Data mapping model.

[cols="1,3"]
|===
|Annotation |Purpose

|ann:data.graph.annotation.Node[]
|Maps a class to a node. The label defaults to the simple name of the class. `labels` sets several labels.

|ann:data.graph.annotation.Relationship[]
|Maps a property to relationships. The type defaults to the property name in upper snake case, for example `actedIn` becomes `ACTED_IN`. `direction` is `OUTGOING` by default, or `INCOMING` or `UNDIRECTED`. A collection maps to many relationships, any other type to one.

|ann:data.graph.annotation.RelationshipProperties[]
|Maps a class whose instances are relationships with properties.

|ann:data.graph.annotation.TargetNode[]
|Marks the property of a relationship class that holds the node at the far end.

|ann:data.graph.annotation.RelationshipId[]
|Marks the identifier of a relationship class, generated by the database.

|ann:data.annotation.MappedProperty[]
|Renames a property.
|===

Nodes are identified by an ann:data.annotation.Id[] property. Identifiers can be:

* Assigned by the application, such as the title of a movie. Saving merges the node on its identifier.
* Generated by Micronaut Data, such as a `UUID` annotated with ann:data.annotation.AutoPopulated[].
* Generated by the database, with ann:data.annotation.GeneratedValue[]. A `String` holds the Neo4j element identifier and a `Long` the numeric identifier.

== Saving relationships

Saving an entity writes its node, then saves the nodes it relates to and creates the relationships between them. A related node that has an identifier is updated rather than created again. Saving does not remove relationships missing from a collection: use an explicit query to delete relationships.

Relationships are not loaded unless a finder asks for them with ann:data.annotation.Join[], see <<graphTraversal, Querying Relationships>>. Collections of relationships that were not fetched are empty.

== Encoding values

Property and parameter values are encoded into values the database accepts by the encoder registered for their type in api:data.graph.runtime.GraphValueEncoders[], or for their nearest supertype. Strings, booleans, numbers and temporal values are written as they are, enums by name, collections and maps element by element, and other values as their string form. Each database replaces encoders for types it stores differently: Apache AGE writes temporal values as ISO-8601 strings, for example.

A bean of type api:data.graph.runtime.GraphValueEncoderRegistrar[] adds encoders for application types, or replaces those of the database:

== Reading with Micronaut Serialization

Nodes and relationships are read with https://micronaut-projects.github.io/micronaut-serialization/latest/guide/[Micronaut Serialization]. ann:data.graph.annotation.Node[] and ann:data.graph.annotation.RelationshipProperties[] make a class `@Serdeable`, so no further annotation is needed. Records, and classes with a public no-argument constructor and setters, get a deserializer generated at compile time. Other classes, such as a class that sets some properties through its constructor and others through setters, and Kotlin classes, are read by the deserializer Micronaut Serialization builds at runtime.

Saving does not use Micronaut Serialization: entities are written through their bean introspections.
