Path finders search the graph between two nodes. Their names start with the kind of search, optionally followed by `By` and the relationship properties to traverse, joined with `Or`. Their first two parameters are the start and end nodes, as entities or identifiers.

snippet::example.PersonRepository[project-base="doc-examples/neo4j-example", source="main", tags="paths", languages="java,kotlin,groovy,python"]

<1> One shortest path following any relationship.
<2> One shortest path following `FOLLOWS` relationships, at most `maxDepth` long.
<3> Every path following `FOLLOWS` relationships, at most 4 long, shortest first.
<4> Whether any path exists.

[cols="1,2"]
|===
|Method name |Result

|`findShortestPath`, `findPath`
|One shortest path

|`findAllShortestPaths`
|Every shortest path

|`findAllPaths`, `findPaths`
|Every path up to the maximum depth, which is required

|`existsPath`
|Whether a path exists

|`countPaths`
|The number of paths up to the maximum depth
|===

ann:data.graph.annotation.PathLimit[] sets the maximum depth, either on the method or on an `int` parameter. The direction follows the relationship properties named after `By`. Without them, paths follow any relationship in either direction.

A variable-length path visits every path up to its depth, so a depth passed as an argument is capped: an argument above `micronaut.data.graph.max-path-depth` (10 by default) is rejected with an `IllegalArgumentException` before the query runs. Raise the limit in configuration when a repository needs deeper searches:

[configuration]
----
micronaut:
  data:
    graph:
      max-path-depth: 20
----

A path is returned as a api:data.graph.model.GraphPath[] holding its nodes, mapped to entities, and its relationships:

<1> Each api:data.graph.model.PathSegment[] holds a relationship and the nodes at its ends, in path order.

== Paths to other entities

A path or relationship finder starts at a node of the repository entity and ends at a node of the same entity, unless the finder says otherwise. The end node is another entity when the name says `To<Entity>`, when the end parameter is an entity of another type, when a `GraphRelationship<F, T>` result names another entity at either end, or when the relationship properties after `By` all point at another entity:

snippet::example.MovieRepository[project-base="doc-examples/neo4j-example", source="main", tags="crossType", languages="java,kotlin,groovy,python"]

<1> `directors` points at `Person`, so the relationships end at a person. `GraphRelationship<F, T>` holds the node the relationship starts at and the node it ends at: a `DIRECTED` relationship starts at the person.
<2> Every path from the movie to the person, at most 3 relationships long. The nodes along the way are of any type, so they are declared as `Object` and mapped to the entity of their labels.
<3> `Between<Start>And<End>` matches each endpoint by its own property.

snippet::example.MovieRepositorySpec[project-base="doc-examples/neo4j-example", tags="crossType", indent="0", languages="java,kotlin,groovy,python"]

<1> The person the relationship starts at.
<2> The node at the end of the path is a `Person`.

Oracle property graph repositories support relationship finders that end at another entity, and reject path finders that do.
