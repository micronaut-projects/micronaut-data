Repositories return Reactor types when they extend api:data.repository.reactive.ReactorCrudRepository[] or declare methods that return `Mono` or `Flux`:

snippet::example.ReactiveMovieRepository[project-base="doc-examples/neo4j-example", source="main", tags="repository", languages="java,kotlin,groovy,python"]

With Neo4j, the reactive operations run on the reactive sessions of the Neo4j Java driver, without blocking a thread while a query runs. A `Flux` streams the rows of a query as the database returns them:

snippet::example.ReactiveMovieRepositorySpec[project-base="doc-examples/neo4j-example", tags="reactive", indent="0", languages="java,kotlin,groovy,python"]

<1> Save the movies, one query after another in the same session.
<2> Then stream the movies released after 1995.
<3> Block only to read the result in the test.

Saving an entity writes its node, its labels and its relationships in sequence, and triggers the same entity events as a blocking save.

== Reactive transactions

A method annotated with `@Transactional` that returns a `Mono` or `Flux` runs in a transaction of the reactive session, which commits when the publisher completes and rolls back when it fails or is cancelled. Reactive repository methods called from it join the transaction through the Reactor context:

snippet::example.ReactiveMovieService[project-base="doc-examples/neo4j-example", source="main", tags="transactional", languages="java,kotlin,groovy,python"]

Apache AGE and Oracle property graphs on JDBC run reactive repository methods on a thread of the I/O executor, in the blocking operations of their JDBC driver. Oracle property graphs can also run on the non-blocking Oracle R2DBC driver, see <<graphOracle, Reactive repositories with R2DBC>>.
