Each relationship in a criterion adds a pattern to the query:

[source,cypher]
----
MATCH (n:Movie), (n)<-[ar0:ACTED_IN]-(a0:Person) WHERE a0.name = $p0 WITH DISTINCT n RETURN n
----

Properties of a relationship with properties are queried the same way, for example `findByRolesRolesArrayContains(String role)` matches movies by the roles stored on `ACTED_IN`.

== Fetching relationships

Relationships are loaded when a finder is annotated with ann:data.annotation.Join[]:

snippet::example.MovieRepository[project-base="doc-examples/neo4j-example", source="main", tags="join", languages="java,kotlin,groovy,python"]

<1> The roles, with the people who played them, and the directors are loaded with the movie.

Without a join a relationship property is left as the entity declares it: `null` for a single node and empty for a collection. Nothing is loaded lazily, and there are no proxies, so a finder that needs related nodes names its joins. A join is always optional: a movie without directors is still returned, with an empty collection, whether or not the property is annotated with `@Nullable`.

Each join adds an `OPTIONAL MATCH` whose results are collected, so the query returns one row per movie:

[source,cypher]
----
MATCH (n:Movie) WHERE n.title = $p0
OPTIONAL MATCH (n)<-[r0:ACTED_IN]-(j0:Person)
WITH n, collect(CASE WHEN r0 IS NULL THEN NULL ELSE {rel: r0, node: j0} END) AS j_roles
OPTIONAL MATCH (n)<-[:DIRECTED]-(j1:Person)
WITH n, j_roles, collect(j1) AS j_directors
RETURN n, j_roles, j_directors
----

A join has no limit of its own. Every node of a joined relationship is collected into the row of its root node, so a node with many relationships returns a large row, and paging bounds the root nodes only, not the nodes collected with them. Join relationships whose size is known to be small. Read a large relationship with an explicit query, which can limit the nodes it collects.

A join path through several relationships also loads the relationships of the related nodes:

snippet::example.MovieRepository[project-base="doc-examples/neo4j-example", source="main", tags="nestedJoin", languages="java,kotlin,groovy,python"]

<1> The directors are loaded with the people they follow.

Each node of the outer relationship is collected with the nodes of its own relationships, so the query still returns one row per movie:

[source,cypher]
----
MATCH (n:Movie) WHERE n.released = $p0
OPTIONAL MATCH (n)<-[:DIRECTED]-(j0:Person)
OPTIONAL MATCH (j0)-[:FOLLOWS]->(j0_0n:Person)
WITH n, j0, collect(j0_0n) AS j0_0
WITH n, collect(CASE WHEN j0 IS NULL THEN NULL ELSE {node: j0, follows: j0_0} END) AS j_directors
RETURN n, j_directors
----

A relationship with properties can only be joined at the start of a join path, as in `@Join("roles.person")`. Oracle property graphs do not support fetch joins.
