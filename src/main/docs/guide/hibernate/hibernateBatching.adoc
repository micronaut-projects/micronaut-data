The `saveAll` and `updateAll` methods of a Micronaut Data JPA Hibernate repository pass every entity to the Hibernate session, which sends the statements when the session is flushed. By default Hibernate sends one statement per entity. Enable JDBC batching to send them in batches:

[configuration]
----
jpa:
  default:
    properties:
      hibernate:
        jdbc:
          batch_size: 50
        order_inserts: true
        order_updates: true
----

`order_inserts` and `order_updates` group the statements of the same entity type, so that cascaded entities don't split the batches.

Hibernate can't batch the inserts of an entity whose id is generated by the database with `GenerationType.IDENTITY`: it has to run each insert to read the generated id. Use a sequence (`GenerationType.SEQUENCE`) with an allocation size that matches the batch size to batch inserts.

The session keeps every entity it saved until the transaction ends, so the memory used by a `saveAll` grows with the number of entities. To load a large number of entities, save them in chunks, each in its own transaction. Flushing and clearing the session in the middle of a transaction also frees the memory, but it detaches every entity of the session, including the entities other code in the transaction still uses.
