When dealing with large datasets in database queries, loading all results into memory at once can lead to OutOfMemoryError (OOM). Micronaut Data JPA Hibernate provides support for streaming query results using `java.util.stream.Stream`, allowing you to process data incrementally without loading everything into memory.

This guide explains how to use streaming effectively, avoid common pitfalls, and manage resources properly.

=== Why Streaming Can Cause OOM Without Detachment

Hibernate maintains a first-level cache (the session cache) that keeps track of all loaded entities. When streaming large result sets without detaching entities, this cache grows indefinitely, potentially leading to OOM errors. Each entity loaded into the session remains managed, consuming memory until the session is cleared or closed.

To mitigate this, you must detach entities after processing or periodically clear the session.

=== Using TransactionOperations to Keep the Session Open

Streams require an open Hibernate session to fetch data lazily. Use `TransactionOperations` to execute operations within a transaction, ensuring the session remains open while consuming the stream.

== Warnings

- **Do not access lazy associations after detaching**: Detached entities cannot load lazy relationships.
- **Consume the stream fully within the transaction**: Partial consumption may leave the session open unexpectedly.
- **Do not leak the stream beyond the method**: Return streams only if consumed immediately; otherwise, convert to lists.
