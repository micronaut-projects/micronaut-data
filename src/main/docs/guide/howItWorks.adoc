Micronaut Data uses two key features of https://micronaut.io[Micronaut]: The https://docs.micronaut.io/latest/api/io/micronaut/inject/visitor/TypeElementVisitor.html[TypeElementVisitor] API and https://docs.micronaut.io/latest/guide/index.html#introductionAdvice[Introduction Advice].

Micronaut Data defines a api:data.processor.visitors.RepositoryTypeElementVisitor[] that at compilation time visits all interfaces in the source tree that are annotated with the ann:data.annotation.Repository[] annotation.

The `RepositoryTypeElementVisitor` uses service loader to load all available api:data.processor.visitors.finders.MethodMatcher[] implementations, sorts them by their order and iterates over them.

TIP: You can add additional method matchers by creating a library that depends on `micronaut-data-processor` and defining the `META-INF/services` definition for the method matcher. The new library should be added to your annotation processor path.

The `MethodMatcher` interface features a `match` method which allows matching a https://docs.micronaut.io/latest/api/io/micronaut/inject/ast/MethodElement.html[MethodElement]. When a matcher returns a `MethodMatch`, its `buildMatchInfo` method is invoked, which returns an instance of api:data.processor.visitors.finders.MethodMatchInfo[]. The first matcher that produces a `MethodMatchInfo` is used to implement the method.

The `MethodMatchInfo` specifies the runtime api:data.intercept.DataInterceptor[] to execute, which typically differs based on the return type and behaviour required, and the query to execute. To build the query, the method matcher translates the method name and parameters into a Jakarta Persistence Criteria query (api:data.model.jpa.criteria.PersistentEntityCriteriaQuery[]), which is the query model shared by all Micronaut Data implementations.

The criteria query is then converted into the equivalent String-based query (native SQL for JDBC and R2DBC, JPA-QL for Hibernate, or a query document for MongoDB and Azure Cosmos) using the api:data.model.query.builder.QueryBuilder[] that is configured by the repository annotation, for example ann:data.jdbc.annotation.JdbcRepository[] with its SQL dialect.

A binding between runtime method parameters and named query parameters is also created.

The visited `MethodElement` is then dynamically annotated with the following information:

* The constructed string-based query (for example SQL or JPA-QL)
* The parameter binding (A map containing the named parameter in the query as key and the name of the method argument as a value)
* The runtime api:data.intercept.DataInterceptor[] to execute.

At runtime all the api:data.intercept.DataInterceptor[] has to do is retrieve the query, read the method parameter values using the parameter binding and execute the query.
