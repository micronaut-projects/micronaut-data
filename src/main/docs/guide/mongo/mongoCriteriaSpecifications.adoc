Micronaut Data MongoDB supports building queries programmatically at runtime using the Jakarta Persistence Criteria API. The repository interfaces, the specification types and how to use them for querying, updating and deleting are the same for all Micronaut Data modules and are described in the <<criteriaSpecifications, Repositories with Jakarta Criteria API>> section, including the async, reactive and coroutine <<otherRepositoryVariations, repository variations>>.

Micronaut Data implements a subset of Jakarta Persistence Criteria API 3.0, which can be used for Micronaut Data MongoDB features. To utilize this feature add the following dependency:

dependency:jakarta.persistence:jakarta.persistence-api[]

Then extend api:data.repository.jpa.JpaSpecificationExecutor[] (or one of its variations) in a ann:data.mongodb.annotation.MongoRepository[] repository:

Micronaut Criteria API currently implements only a subset of the API. Most of it is internally used to create queries with predicates and projections.

Currently, not supported JPA Criteria API features:

- Joins with custom `ON` expressions and typed join methods like `joinSet` etc
- Sub-queries
- Collection operations: `isMember` etc
- Custom or tuple result type
- Transformation expressions like concat, substring etc.
- Cases and functions

To check whether a list or array field contains a value, the `ArrayContains` / `CollectionContains` criteria available for <<mongoRepositories, repository methods>> can also be used in a predicate specification through api:data.model.jpa.criteria.PersistentEntityCriteriaBuilder[]:
