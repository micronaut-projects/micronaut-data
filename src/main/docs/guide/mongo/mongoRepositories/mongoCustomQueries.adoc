Micronaut Data MongoDB introduces a few annotations that can be used to define custom queries and modify default options:

.Micronaut Data MongoDB annotations
[cols=2*]
|===
|*Annotation*
|*Description*

|ann:data.mongodb.annotation.MongoFindQuery[]
|Allows defining a custom find method execution with values for filtering, sorting, projection and collation.

|ann:data.mongodb.annotation.MongoAggregateQuery[]
|Allows defining a custom aggregate method execution with a value for the pipeline.

|ann:data.mongodb.annotation.MongoUpdateQuery[]
|Allows defining a custom update method execution with values for filter, update and collation.

|ann:data.mongodb.annotation.MongoUpdateReturningQuery[]
|Allows defining a custom single-document update-returning execution with values for filter, update, sort, projection, collation and `returnDocument`.

|ann:data.mongodb.annotation.MongoDeleteQuery[]
|Allows defining a custom delete method execution with values for filter and collation.

|ann:data.mongodb.annotation.MongoFilter[]
|Allows defining a custom filter value for operations that support it. Can be used on annotation to create a predefined filter annotation.

|ann:data.mongodb.annotation.MongoSort[]
|Allows defining a custom sort value for operations that support it. Can be used on repository class to define a default sort or to create a predefined sort annotation.

|ann:data.mongodb.annotation.MongoProjection[]
|Allows defining a custom projection value for operations that support it. Can be used on repository class to define a default projection or to create a predefined projection annotation.

|ann:data.mongodb.annotation.MongoCollation[]
|Allows defining a custom collation value for operations that support it. Can be used on repository class to define a default collation or to create a predefined collation annotation.

|ann:data.mongodb.annotation.MongoAggregateOptions[]
|The aggregation operation options.

|ann:data.mongodb.annotation.MongoFindOptions[]
|The find operation options.

|ann:data.mongodb.annotation.MongoUpdateOptions[]
|The update operation options.

|ann:data.mongodb.annotation.MongoDeleteOptions[]
|The delete operation options.

|===

Custom queries for MongoDB are defined in JSON and method parameters can be referenced as variables prefixed with `:`.

Mongo update methods can either return the number of updated documents (for example `long`, `int` or `boolean`) or return a single updated document.
Use ann:data.mongodb.annotation.MongoUpdateQuery[] for count/acknowledgement update methods.
Use ann:data.mongodb.annotation.MongoUpdateReturningQuery[] for single-document update-returning methods.

For ann:data.mongodb.annotation.MongoUpdateReturningQuery[], the default `returnDocument` value is `ReturnDocument.BEFORE`.
If you want the updated state returned, set `returnDocument = ReturnDocument.AFTER` explicitly.

[source,java]
----
@MongoUpdateReturningQuery(filter = "{_id: {$eq: :id}}", update = "{$inc:{totalPages: 1}}", returnDocument = ReturnDocument.AFTER)
Book incrementTotalPagesAfter(String id);
----

NOTE: MongoDB can only return a single updated document for an update operation (using `findOneAndUpdate`).
Update-returning methods must use a single blocking result type and ann:data.mongodb.annotation.MongoUpdateReturningQuery[].
Collection/iterable and `void` return types are rejected for ann:data.mongodb.annotation.MongoUpdateReturningQuery[].
If you use a scalar return type (for example `String`), configure a matching projection with `project`.
If your filter can match multiple documents, use `sort` to control which document is selected by `findOneAndUpdate`.
`@MongoUpdateQuery` and `@MongoUpdateReturningQuery` are mutually exclusive and must not be used together on the same method.
