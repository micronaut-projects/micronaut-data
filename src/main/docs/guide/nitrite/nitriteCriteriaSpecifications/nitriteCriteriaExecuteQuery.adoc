== Association Queries

Nitrite supports Criteria queries on associations:

* **MANY_TO_ONE**: Filter by association properties (e.g., `Book.author.name = "Stephen King"`)
* **ONE_TO_MANY**: Reverse lookups (e.g., `Author.books.title = "The Stand"`)

For reverse lookups on ONE_TO_MANY associations, the query builder preserves the property path and Nitrite executes a sub-query to find matching parent entities.

Example of a reverse lookup method:

snippet::example.AuthorRepository[project-base="doc-examples/nitrite-example", source="main", tags="reverse-lookup"]

The above method finds authors who have written a book with the specified title. Internally, Nitrite:

. Queries the `book` collection for documents where `title` matches the parameter
. Collects the `author_id` foreign keys from matching books
. Queries the `author` collection for documents with matching IDs

This approach allows natural property-path queries while efficiently handling the reverse lookup through the foreign key relationship.

NOTE: Reverse lookups on ONE_TO_MANY associations require that the child entity (e.g., `Book`) has a foreign key reference to the parent entity (e.g., `Author`). The `@Relation` annotation with `Kind.MANY_TO_ONE` on the child entity establishes this relationship.

== Query Format

Nitrite-specific notes:

- Parameters are bound positionally using placeholders of the form `"$mn_qp:<index>"`.
- `Instant` values are stored and queried as ISO-8601 string representations; query parameters are normalized to match the stored representation.
- Numeric equality comparisons are tolerant to representation differences introduced by the mapping layer (for example `Long` vs `BigDecimal`).
- Association queries use dot notation for property paths (e.g., `book_author.title` for `Author.books.title`).
- Date/time field names use snake_case format in aggregation queries (e.g., `last_updated`).
