[[nitriteQuickStart]]
Micronaut Launch does not currently offer a dedicated `data-nitrite` feature. The quickest way to get started is to add the Nitrite implementation and the Micronaut Data annotation processors to an existing Micronaut application.

== Dependency Setup

Add the following dependencies to your annotation processor path:

dependency:io.micronaut.data:micronaut-data-document-processor[scope="annotationProcessor"]

dependency:io.micronaut.data:micronaut-data-nitrite[scope="annotationProcessor"]

NOTE: For Kotlin, add both dependencies in https://docs.micronaut.io/4.4.3/guide/#kaptOrKsp[kapt or ksp scope], and for Groovy add both in compileOnly scope.

`micronaut-data-nitrite` is needed on the annotation processor path as well as the compile path: it carries the `NitriteQueryBuilder` that ann:data.nitrite.annotation.NitriteRepository[] names, and Micronaut Data resolves that builder at compilation time. Without it, repository methods are compiled against the default JPQL query builder instead of into Nitrite filters, and Nitrite-specific features such as projections, association lookups and `$regex` queries are lost.

Then add a compile-scoped dependency on the Nitrite implementation:

dependency:io.micronaut.data:micronaut-data-nitrite[scope="implementation"]

== Saving an Instance (Create)

To save an instance use the `save` method of the `CrudRepository` interface:

snippet::example.BookRepositoryExample[project-base="doc-examples/nitrite-example", source="main", tags="save", indent="0"]

The `save` method uses **upsert semantics**:

- If the entity's ID is `null`, a new document is inserted and the ID is generated
- If the entity has an existing ID, the document is updated (replaced) if found, or inserted if not found

This means `save()` can be used for both creating new entities and updating existing ones when you know the entity's ID.
