[[nitriteSpatial]]
== Spatial Queries

Micronaut Data Nitrite supports spatial queries through the optional https://nitrite.dizitart.com/java-sdk/modules/spatial/index.html[Nitrite Spatial] module. This enables storage and querying of geometric data types such as points, lines, and polygons.

=== Setup

Add the following dependencies to your project:

dependency:org.dizitart:nitrite-spatial[scope="runtime"]

And the Jackson JTS library:

dependency:com.graphhopper.external:jackson-datatype-jts[version="2.21.0", scope="runtime"]

The `nitrite-spatial` module provides spatial indexing and filtering capabilities. The `jackson-datatype-jts` library handles JSON serialization of JTS Geometry objects.

=== Geometry Types

Micronaut Data Nitrite uses the https://locationtech.github.io/jts/[JTS (Java Topology Suite)] library for geometry types. Common geometry types include:

- `Point`: A single coordinate (x, y)
- `LineString`: A sequence of connected line segments
- `Polygon`: A closed shape defined by a ring of coordinates
- `MultiPoint`, `MultiLineString`, `MultiPolygon`: Collections of geometry types

IMPORTANT: JTS Coordinate order is **(longitude, latitude)** or **(x, y)**, NOT (latitude, longitude). This is a common source of errors. For example, to create a point for New York City (40.7128° N, 74.0060° W), use:

=== Limitations

- Spatial queries require the `nitrite-spatial` module at runtime
- Geometry fields must use JTS types from `org.locationtech.jts.geom`
- Spatial indexes are automatically created for fields annotated with `@SpatialIndex`
- The `$near` filter uses planar distance calculations (not geodesic/spherical)
- For geographic applications, consider the coordinate system and distance units carefully
