An entity maps to one index, named after `@Searchable(name)` or, when that is empty, after `@MappedEntity`, behind the optional `index-prefix`. Properties become document fields with the names Micronaut Serialization gives them.

<1> `language` selects the built-in language analyzer of the store (`english`, `german`, ...). `simple` or `none` map to the `standard` analyzer.
<2> `weight` becomes a query-time boost (`title^10`) when several fields are searched: `HIGH` 10, `MEDIUM` 5, `LOW` 2, `LOWEST` 1.
<3> A `@SearchField` without options is an analysed `text` field.

== Index mapping

When `micronaut.data.search.create-indexes` is enabled, Micronaut Data creates the index of a `@Searchable` entity on startup with an explicit mapping for its search fields; every other string, enum and UUID property is a `keyword`, so the derived queries compare it exactly, and the remaining properties are mapped dynamically by the store:

|===
|`@SearchField` type |Mapping

|`TEXT` |`text` with the language analyzer, plus a `keyword` sub-field (`<field>.keyword`) used for exact matches and sorting
|`KEYWORD` |`keyword`
|`AUTOCOMPLETE` |`search_as_you_type` with the language analyzer
|===

`@SearchField(analyzer = "...")` overrides the analyzer of one field with any analyzer the index defines. For settings and analyzers beyond this mapping, create the index with your own tooling before the application starts; an existing index is left untouched.

== Settings and hand-written mappings

ann:data.annotation.search.SearchIndexSettings[] on the entity carries the JSON of the create-index request's `settings`, merged over the store defaults: shards and replicas, or an `analysis` section defining custom analyzers that `@SearchField(analyzer)` can then name. ann:data.annotation.search.SearchMapping[] on a property carries the JSON of that field's mapping and replaces the generated one, for options the portable annotations do not expose such as `fielddata`, `ignore_above` or a `dense_vector` with its own index options. Both apply when schema generation or `SearchIndexOperations` creates the index; an existing index is not updated.

== Vectors

A api:data.model.vector.Vector[] property is mapped as a `dense_vector` on Elasticsearch and as a `knn_vector` with the Lucene HNSW engine on OpenSearch, both with cosine similarity; its dimension comes from `@Column(length)`, which OpenSearch requires. Vectors are stored as JSON arrays of numbers. OpenSearch indexes are created with `index.knn` enabled.

== Ids

The document id is the entity id. A `String` id left `null` is generated by the store; a `UUID` id is generated by Micronaut Data; numeric ids must be assigned by the application. The id is also kept in the document source under its property name, which cursored paging uses as its tiebreaker. A `@Version` property holds the document version, see the <<searchDocumentQueries, queries section>>.
