Micronaut Data can use Elasticsearch or OpenSearch as a store: entities are indexed as documents, repositories offer the usual CRUD, paging and derived finders, and full-text search is a first-class repository feature. Both stores share one implementation in `micronaut-data-search-document`; the client modules differ only in the transport.

NOTE: Elasticsearch and OpenSearch support is experimental.

== Dependencies

For Elasticsearch, add the Micronaut Data Elasticsearch module, which pulls in https://micronaut-projects.github.io/micronaut-elasticsearch/latest/guide/[Micronaut Elasticsearch] and the official Java client:

dependency:io.micronaut.data:micronaut-data-search-elasticsearch[]

For OpenSearch, add the OpenSearch module together with a https://micronaut-projects.github.io/micronaut-opensearch/latest/guide/[Micronaut OpenSearch] transport, for example `micronaut-opensearch-httpclient5`:

dependency:io.micronaut.data:micronaut-data-search-opensearch[]

Use one of the two modules per application. Each registers its blocking and its async transport under the name `default`, which the repositories select, so with both on the classpath there are two `default` transports and injecting a repository fails with a `NonUniqueBeanException`.

Entities are serialised with Micronaut Serialization, so compile them with the document annotation processor, which marks `@MappedEntity` classes serialisable, and add the search module to the processor path so the repository query builder is found:

[source,groovy]
----
annotationProcessor("io.micronaut.data:micronaut-data-document-processor")
annotationProcessor("io.micronaut.data:micronaut-data-search-document")
----

Configure the client of the store you use, for example:

[configuration]
----
elasticsearch:
  http-hosts: http://localhost:9200
----

or

[configuration]
----
micronaut:
  opensearch:
    httpclient5:
      http-hosts: http://localhost:9200
----

== Repositories

Annotate repositories with ann:data.search.elasticsearch.annotation.ElasticsearchRepository[] or ann:data.search.opensearch.annotation.OpenSearchRepository[]:

snippet::example.BookRepository[project-base="doc-examples/elasticsearch-search-example", source="main", tags="repository"]

<1> api:data.repository.SearchRepository[] adds `search(String)` and `countHits(String)` over every search field; `CrudRepository` gives the usual operations. Ids are the document ids: use a `String` or a `UUID`, both generated by Micronaut Data when `null`.
<2> `Search` after a property matches that property only, as a `simple_query_string` on the field.
<3> A `search` method returning `SearchResults` carries the `_score` of each hit and sorts by it.
<4> `SearchPhrase` requires the terms adjacent and in order.
<5> Search keywords combine with any other predicate in a `bool` query.

== Configuration

|===
|Property |Default |Purpose

|`micronaut.data.search.index-prefix` | |Prefix added to every index name, for per-environment indexes
|`micronaut.data.search.refresh` |`WAIT_FOR` |Refresh policy of writes: `NONE`, `WAIT_FOR` or `TRUE`. `WAIT_FOR` makes a saved entity searchable before `save` returns
|`micronaut.data.search.create-indexes` |`true` |Create the index of every entity a document repository stores, and of every `@Searchable` entity no other repository stores, on startup when it does not exist
|`micronaut.data.search.max-results` |`10000` |The most hits a query without a `Pageable` or limit fetches, including a `@Query` body or a `SearchQueryExecutor` search without a `size`; it is also the `k` of a vector search without a limit, up to 10,000
|`micronaut.data.search.unique-result-on-find-one` |`false` |Whether a query for one entity throws `NonUniqueResultException` when it matches several documents, as Jakarta Data requires, instead of returning the first hit; it costs a second hit per query
|`micronaut.data.search.schema-generate` |`CREATE` |What happens to the indexes on startup: `CREATE` creates the missing ones, `CREATE_DROP` drops and recreates every index, deleting its documents, and `NONE` leaves them alone. `create-indexes: false` is the same as `NONE`
|`micronaut.data.search.bulk-size` |`1000` |Largest number of documents `saveAll` sends in one bulk request; a larger batch is sent as several requests in sequence
|===

`saveAll` indexes the entities with bulk requests, which are not atomic: when the store rejects some documents of a request, it still writes the others. The repository then stores the id of each written entity and fires its post-persist event, and throws a api:data.search.document.runtime.BulkIndexException[] that names every rejected document and whose `getIds()` gives the id of each document of the failing request, `null` for the rejected ones; the entities that were not written keep the id generated for them. The requests before the failing one were written in full and the ones after it are not sent. When a rejected document of a versioned entity conflicted with the stored version, `saveAll` throws an api:data.exceptions.OptimisticLockException[] instead, whose cause is that `BulkIndexException`.
