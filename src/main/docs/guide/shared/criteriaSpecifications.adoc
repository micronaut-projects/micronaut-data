In some cases, you need to build a query programmatically and at the runtime; for that, Micronaut Data supports Jakarta Persistence Criteria API 3.0.

The API described in this section is the same for every Micronaut Data module. With Micronaut Data JPA the criteria are executed by Hibernate, while Micronaut Data JDBC / R2DBC, MongoDB and Azure Cosmos implement a subset of the Criteria API themselves. For the additional dependency these modules require and the Criteria API features they do not support, see:

- <<dbcCriteriaSpecifications, Criteria API with JDBC / R2DBC>>
- <<mongoCriteriaSpecifications, Criteria API with MongoDB>>
- <<azureCosmosCriteriaSpecifications, Criteria API with Azure Cosmos>>

[.lang-python]
NOTE: In Python declare the specification methods on the repository itself: Micronaut Data matches them by their `PredicateSpecification` / `QuerySpecification` / `UpdateSpecification` / `DeleteSpecification` parameter types. A specification is a plain Python function or lambda, and since `and`, `or` and `not` are Python keywords, the corresponding `CriteriaBuilder` methods are called as `and_`, `or_` and `not_`.

Each method expects a "specification" which is a functional interface with a set of Criteria API objects intended to build a query programmatically.
