To explicitly insert data, use `insert` and `insertAll` from the built-in CRUD repository interfaces or define a repository method that requires an insert operation.
Unlike `save` and `saveAll`, explicit insert methods always issue an insert and may fail if the entity already exists.

[source,java]
----
Book insert(Book entity);
List<Book> insertAll(Iterable<Book> entities);
----

The built-in CRUD repository variants include insert methods with their native return types:

[cols=2*]
|===
|*Repository*
|*Insert methods*

|api:data.repository.CrudRepository[]
|`S insert(S entity)`, `List<S> insertAll(Iterable<S> entities)`

|api:data.repository.async.AsyncCrudRepository[]
|`CompletableFuture<S> insert(S entity)`, `CompletableFuture<? extends Iterable<S>> insertAll(Iterable<S> entities)`

|api:data.repository.reactive.ReactiveStreamsCrudRepository[]
|`Publisher<S> insert(S entity)`, `Publisher<S> insertAll(Iterable<S> entities)`

|api:data.repository.reactive.ReactorCrudRepository[]
|`Mono<S> insert(S entity)`, `Flux<S> insertAll(Iterable<S> entities)`

|api:data.repository.reactive.RxJavaCrudRepository[]
|`Single<S> insert(S entity)`, `Flowable<S> insertAll(Iterable<S> entities)`

|api:data.repository.kotlin.CoroutineCrudRepository[]
|`suspend fun <S : E> insert(entity: S): S`, `fun <S : E> insertAll(entities: Iterable<S>): Flow<S>`
|===

Custom insert methods must accept a single argument that is the entity and start with `persist`, `insert`, or `store`, or be annotated with ann:data.annotation.Insert[].
To persist multiple entities the method needs to accept `java.lang.Iterable` of the entity.
Methods that start with `save` perform a conditional save: an entity without an identity value is inserted, and an entity with a generated or always auto-populated identity value already present is updated.
Entities with non-generated assigned identities are inserted by default.

To temporarily restore the Micronaut Data 4 behavior where repository `save` and `saveAll` always issue insert operations, set `micronaut.data.save-as-insert` to `true`.
For entities with non-generated assigned identity values, `micronaut.data.save-assigned-id-fallback-to-update` can be enabled to try an insert first and fall back to update when the insert fails because the row already exists.
This fallback is not applied to entities that define a version property for optimistic locking; a duplicate insert failure is propagated.

TIP: It is not possible to use the entity as the return type in partial updates because it would require an additional select to retrieve the additional information. A number type (int, long, etc.) can be returned to indicate the number of rows updated. The updated row count should be checked in most scenarios to ensure the update actually affected the row.
