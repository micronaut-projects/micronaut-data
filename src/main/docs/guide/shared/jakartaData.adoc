Micronaut Data provides implementation support for the https://jakarta.ee/specifications/data/[Jakarta Data specification], allowing developers to leverage Jakarta Data's standardized approach to data access within Micronaut applications. This integration combines Micronaut's efficient Ahead of Time (AoT) compilation capabilities with Jakarta Data's standardized repository pattern. The Jakarta Data specification provides an API to simplify data access. It enables the Java developer to focus on the data model, while delegating away the complexities of data persistence. To make this possible, Jakarta Data includes a variety of features such as pre-built interfaces for data access, offset and cursor based pagination strategies, and the ability to compose custom query methods that the framework implements.

== Configuration
To use Jakarta Data annotations in your Micronaut project, ensure you have the following dependency:

dependency:jakarta.data:jakarta.data-api[]

== Key features

Micronaut Data supports a combination of Jakarta Data annotations and repositories with Micronaut annotations.
It's still required to use `@JdbcRepository`, `@MongoRepository` etc to specify which data implementation should be used.

=== Core Repository Features
- Repository pattern with annotation `@Repository`
- Standard CRUD operations out of the box
- Type-safe query methods
- Automatic query derivation from method names

=== Query Capabilities
- Method name-based query generation
- Custom queries with annotation `@Query`
- Dynamic finder methods with `@Find`
- Result ordering with `@OrderBy`
- Limiting results with `Limit`, and offset or cursor based pagination with `PageRequest`

=== Data Modification
- Entity insertion with `@Insert`
- Updates with `@Update`
- Persistence with `@Save`
- Deletion with `@Delete`

== Repository Mapping

The implementation combines the benefits of Micronaut's efficient compilation and runtime characteristics with Jakarta Data's standardized approach to data access.

For more detailed information about individual features and capabilities, please refer to the official Micronaut Data documentation and the https://jakarta.ee/specifications/data/[Jakarta Data specification].

== Jakarta Data Annotations

=== @Repository
The core annotation that marks an interface as a Jakarta Data repository.

[source.multi-language-sample,java]
----
@Repository
public interface UserRepository {
    // repository methods
}
----

[source.multi-language-sample,kotlin]
----
@Repository
interface UserRepository {
    // repository methods
}
----

[source.multi-language-sample,groovy]
----
@Repository
interface UserRepository {
    // repository methods
}
----

NOTE: The default implementation is for JPA, add `@JdbcRepository`, `@MongoRepository` etc. for correct implementation

=== @OrderBy
Specifies the ordering of query results. The annotation is repeatable; each occurrence adds one sort criterion, applied in the order declared.

[source.multi-language-sample,java]
----
@Repository
public interface UserRepository {
    @Find
    @OrderBy("lastName")
    @OrderBy("firstName")
    List<User> findAll();
}
----

[source.multi-language-sample,kotlin]
----
@Repository
interface UserRepository {
    @Find
    @OrderBy("lastName")
    @OrderBy("firstName")
    fun findAll(): List<User>
}
----

[source.multi-language-sample,groovy]
----
@Repository
interface UserRepository {
    @Find
    @OrderBy("lastName")
    @OrderBy("firstName")
    List<User> findAll()
}
----


== Query Annotations

=== @Find
Defines a query from the method parameters: each parameter annotated with `@By` restricts the entity attribute it names. The method name is not parsed.

[source.multi-language-sample,java]
----
@Repository
public interface UserRepository {
    @Find
    List<User> byEmail(@By("email") String email);
}
----

[source.multi-language-sample,kotlin]
----
@Repository
interface UserRepository {
    @Find
    fun byEmail(@By("email") email: String): List<User>
}
----

[source.multi-language-sample,groovy]
----
@Repository
interface UserRepository {
    @Find
    List<User> byEmail(@By("email") String email)
}
----

interface UserRepository {

=== Limiting results
Pass a `jakarta.data.Limit` parameter to restrict the number of results. `Limit.of(10)` returns at most 10 results, and `Limit.range(21, 30)` returns results 21 to 30 (positions start at 1), which also covers offset based access. For paging with totals use `PageRequest` as described in <<_pagination, Pagination>> below.

[source.multi-language-sample,java]
----
@Repository
public interface UserRepository {
    List<User> findByLastName(String lastName, Limit limit);
}

// usage
userRepository.findByLastName("Smith", Limit.of(10));
userRepository.findByLastName("Smith", Limit.range(21, 30));
----

[source.multi-language-sample,kotlin]
----
@Repository
interface UserRepository {
    fun findByLastName(lastName: String, limit: Limit): List<User>
}

// usage
userRepository.findByLastName("Smith", Limit.of(10))
userRepository.findByLastName("Smith", Limit.range(21, 30))
----

[source.multi-language-sample,groovy]
----
@Repository
interface UserRepository {
    List<User> findByLastName(String lastName, Limit limit)
}

// usage
userRepository.findByLastName("Smith", Limit.of(10))
userRepository.findByLastName("Smith", Limit.range(21, 30))
----


== Repository Method Conventions
Besides annotations, Jakarta Data also supports method name conventions for common queries:

[source.multi-language-sample,java]
----
@Repository
public interface UserRepository {
    // Derived finder methods
    List<User> findByLastName(String lastName);
    Optional<User> findByEmail(String email);
    List<User> findByAgeGreaterThan(int age);

    // Count methods
    long countByStatus(String status);

    // Existence checks
    boolean existsByEmail(String email);

    // Delete methods
    void deleteByLastName(String lastName);
}
----

[source.multi-language-sample,kotlin]
----
@Repository
interface UserRepository {
    // Derived finder methods
    fun findByLastName(lastName: String): List<User>
    fun findByEmail(email: String): Optional<User>
    fun findByAgeGreaterThan(age: Int): List<User>

    // Count methods
    fun countByStatus(status: String): Long

    // Existence checks
    fun existsByEmail(email: String): Boolean

    // Delete methods
    fun deleteByLastName(lastName: String)
}
----

[source.multi-language-sample,groovy]
----
@Repository
interface UserRepository {
    // Derived finder methods
    List<User> findByLastName(String lastName)
    Optional<User> findByEmail(String email)
    List<User> findByAgeGreaterThan(int age)

    // Count methods
    long countByStatus(String status)

    // Existence checks
    boolean existsByEmail(String email)

    // Delete methods
    void deleteByLastName(String lastName)
}
----

=== Jakarta Data Exceptions

Micronaut Data will convert exceptions to Jakarta Data variations only if the repository is annotated with `@jakarta.data.repository.Repository` or the method is using any other Jakarta Data annotations `@jakarta.data.repository.Find`, `@jakarta.data.repository.Save` etc.
