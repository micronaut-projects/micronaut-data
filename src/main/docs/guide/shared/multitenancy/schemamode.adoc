NOTE: You can use property `schema-generate-names` to specify multiple schemas to be created and initialized for testing.

The `schema-generate-names` property is optional. If it is omitted, schema generation uses the datasource's default schema. Configure it when schema generation should create and initialize the mapped tables in each named tenant schema, for example, in tests or demos. For production applications, use a database migration tool to create the tenant schemas and their tables.

NOTE: On Oracle, a schema is a database user. Schema generation creates each name in `schema-generate-names` as a user with `NO AUTHENTICATION` and unlimited quota on the database default tablespace, and reuses a user that already exists. The datasource user therefore needs the `CREATE USER` privilege, plus `ANY` privileges (such as `CREATE ANY TABLE` and `INSERT ANY TABLE`) to create and use tables in other schemas.

Tenant values resolved in `SCHEMA` mode are logical schema names. Pass the name without database-specific quoting, such as `tenant-a`; do not pass values already wrapped in `"..."`, backticks, or square brackets. Micronaut Data applies the appropriate identifier quoting for the configured dialect when switching or creating schemas. A tenant resolver only selects the schema name: applications must still ensure that it returns only schemas the current caller is allowed to access.
